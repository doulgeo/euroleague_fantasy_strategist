How this works

This is a personal tool for this 12-manager draft-mode league, not an official EuroLeague product. Projections are a transparent heuristic, not a guarantee - use judgment alongside them.

The league's rules, in brief

Each manager's roster is exactly 13 players: 5 Guards, 5 Forwards, 3 Centers. Each real EuroLeague player can belong to only one manager league-wide (draft mode).

Before each round, a manager picks an active squad of 10 from their 13 - the other 3 are excluded and score zero, no matter what. Within the active 10:

5 Starters
Full points. One is captain and doubles (2x) their score.
1 Sixth man
Full points too, but never captain-eligible.
4 Bench
Half points - automatic, whether or not they're ever swapped in.

The 5 starters must form one of three valid shapes: 2-2-1, 2-1-2, or 3-1-1 (Guard-Forward-Center) - always at least 2 Guards. A round is played over two days; points from day 1 are banked permanently, and on day 2 you can swap a full-scoring slot for a same-position bench player who still has a game left, promoting them to full points. Team win gives a +10% bonus to that player's round score. Full detail (including the day-1/day-2 "golden rule") is in docs/game_rules.md in the repo.

The Lineup page applies all of this for a chosen manager and round - see "Lineup builder" below.

Scoring: PIR

PIR (Performance Index Rating) is the fantasy currency, not raw points:

Point scored, rebound, assist, steal, block performed, foul drawn+1 each
Turnover, block suffered, foul committed, missed shot/free throw-1 each

How projections are calculated

Deliberately simple and auditable - no machine learning. For each player, using only games strictly before the projection date (so it never "cheats" by seeing the future):

Projected value ("Proj+Bonus")
A recency-weighted average of the player's last 10 played games (more recent games count more), plus a bonus scaled to their team's win rate over its last 10 games (+10% of the base projection if the team's been winning consistently).
Games sampled ("n")
How many of the last-10 games actually went into that average. Fewer than 3 games and no projection is built at all - too little signal.
Which season's data
If the current season already has synced games, only those count. Otherwise it falls back to using all of last season's games. This is a hard switch, not a blend - early in a new season, a returning player with only 1-2 games so far can temporarily show as unprojected until they hit 3 games in the new season.

The draft board

VORP
Value over replacement: how much better a player projects than the last player at their position who'd plausibly still get drafted across all 12 managers. Makes positions comparable - a scarce Center can rank above a slightly-higher-projected Guard once scarcity is factored in.
Tiers / "tier break"
Within a position, a tier break marks an unusually large drop-off to the next player (bigger than that position's average gap). Players within the same tier are roughly interchangeable - if your target gets drafted, don't reach for a specific name, grab anyone else in that tier. Only shown in the default sort (Projected value, high to low) - it's not meaningful once you re-sort by something else.
NEW badge
This player has no EuroLeague box-score history in this project's local data (E2023 onward) - a new signing, a rookie, or a club new to the league itself. Their projection is a placeholder of 0.0 rather than a guess, since there's genuinely no data yet to base one on. Their team is still shown correctly, from the current roster source (see below).
EST badge
Shown alongside NEW when that 0.0 placeholder has been replaced by a manually-set estimate instead (see set_manual_projection.py) - typically the result of researching the player (recent form/role, other-league stats) rather than computing from EuroLeague box scores, since none exist yet. Treat it as an informed guess, not a backtested projection.
GONE badge
The mirror image of NEW - this player has EuroLeague history but isn't part of the current roster source at all (their club may have left the competition, they've been released/gone unsigned, or - before round 1 of a new season - they simply haven't been re- registered anywhere yet). These players never appear on the draft board or as a transfer suggestion - they're only shown, greyed out, on a manager's own roster page if already owned, since their old team is now stale and they can't really be acquired. Treat a GONE player on your roster as a drop/trade candidate.
Filter and sort
Filter by position and/or team, and sort by any column (value, VORP, games sampled, name, or team), ascending or descending.
Roster composition source
Who's on which team, at what position, comes primarily from a user-maintained Google Sheet tracking the real EuroLeague Fantasy game's actual draft pool (synced via sync_fantasy_pool.py, see "Keeping the data fresh" below) - found to be more complete and up to date than EuroLeague's own official roster data, especially pre-season. A sheet player who already has EuroLeague box-score history (this season or a prior one) keeps that link automatically, even if their new club hasn't officially re-registered them with EuroLeague yet; a genuinely new player gets the NEW-badge placeholder above. If the sheet hasn't been synced yet, EuroLeague's own roster data is used instead.

Draft, ownership, and transactions

Someone (the commissioner) manually logs what actually happens in the real league: draft picks, trades, free-agent adds, and drops. A player can only be owned by one manager at a time - drafting or trading for an already-owned player is rejected. A trade is logged as a linked pair (a shared "group" ID ties the two legs together in the transaction history). Transfer windows sit between rounds in this league, not continuously open.

Transfer suggestions

For a manager's full 13-player roster, this looks for same-position upgrades: any unowned free agent projecting meaningfully higher than a rostered player at the same position. It's naive by design - it doesn't account for a manager's active-squad exclusion choices or bye weeks, just raw projected value at the same position.

Lineup builder

For a chosen manager and round, this makes three decisions in sequence, each one feeding the next - see "The league's rules, in brief" above for the three-tier scoring model and the day-1/day-2 golden rule all three follow. Needs the season schedule to be synced for the round in question - the regular box-score sync (see below) now also refreshes it. Like Transfer suggestions, this is a live, recomputed-on-every-visit recommendation, not a saved record of what a manager actually did.

1. Which 3 of 13 to exclude
Every one of the 286 possible 3-player exclusion combinations is tried, not just "cut the 3 lowest-projected players": for each one, the tool builds the full day-1 lineup and simulates the day-2 swap for the remaining 10, then keeps whichever exclusion leads to the highest final total. This matters because a benched player keeps swap-in option value an excluded player never gets back - a player projected slightly lower than another might still be worth benching rather than excluding, if their game falls on day 2 and gives them swap-in upside the other player doesn't have.
2. The day-1 lock (starters, 6th man, captain, formation)
The "golden rule": each of the 6 full-scoring slots (5 starters + 6th man) is filled by preferring a player whose team plays on the round's earliest date over one who only plays later - projected value only breaks ties within the same availability, it never overrides it. The reasoning: a full slot given to a day-1 player stays flexible (day 2, you can judge them on real results and keep-or- demote), while a full slot wasted on a day-2 player before they've even played has thrown away that same-round information advantage for nothing. Formation (2-2-1 / 2-1-2 / 3-1-1) defaults to "Auto": all three are tried, each one carried all the way through a simulated day-2 swap, and whichever leads to the highest simulated final total is locked in - not just whichever fields the most day-1 players on paper. Force one manually with the dropdown to see what a specific shape would do instead. Captain is simply the highest-projected of the 5 chosen starters.
3. The day-2 swap plan
Once day 1's games are over (or still pre-round, using projections for everyone), every day-1 full-slot player becomes "flexible": keep them at full rate, or demote them to the bench - which halves the points they already earned, it doesn't protect them. Every player who hasn't played yet is flexible too, regardless of where they started. The one player who is not flexible is a day-1 bench player who's already played - the real rules never let you swap in someone who's already played, so they're locked there for good. From that flexible pool, the tool re-solves for the best possible formation + starters + 6th man + captain by projected (or, once synced, actual) value alone - no day-1-first tiebreak this time, since this is the last decision point and there's no future swap left to protect optionality for. If day 1's actual results are already synced by the time you view the page, those real scores are used instead of the pre-round projection for anyone who's already played, since a swap decision made on a since-proven-wrong projection is a real risk (see game_rules.md), not just a missed upside.
Total Projected Score box
No-swap total, recommended (post-swap) total, and the gain between them - computed with that same "actual PIR if already played, else projection" value used for the swap decision itself, so the numbers shown always match the reasoning behind the recommendation.
Pitch view
The court graphic above each table is a visual of the exact same day-1/day-2 lineup objects - starters grouped by position (Center nearest the hoop, then Forward, then Guard), captain marked, and a bench column with the 6th man tagged and a checkmark for everyone in the active 10. No real player photos exist in EuroLeague's data (their API returns an empty image for every player), so each player is shown as a monogram instead.

Keeping the data fresh

This app only ever reads the local database - it never calls the live EuroLeague API itself, so pages load fast and never hit a rate limit. Someone with terminal access needs to run these periodically:

sync_db.py
Pulls newly played box scores (run after each gameweek).
sync_rosters.py
Refreshes current club rosters from EuroLeague's own data (run before a draft, or whenever transfer news breaks - not tied to gameweeks). Still kept fresh even though the Fantasy pool sheet is now the primary composition source - used as a fallback identity lookup and for when the sheet hasn't been synced.
sync_fantasy_pool.py
Refreshes the real EuroLeague Fantasy draft pool from the Google Sheet (run whenever the sheet changes - it's meant to be kept current). This is the primary source of who's on which roster; see "Roster composition source" above.

If the draft board looks stale (wrong teams, missing new signings, or projections not reflecting recent games), that's the fix.
