How this works

This is a personal tool for this 12-manager draft-mode league, not an official EuroLeague product. Projections are a transparent heuristic, not a guarantee - use judgment alongside them.

The league's rules, in brief

Each manager's roster is exactly 13 players: 5 Guards, 5 Forwards, 3 Centers. Each real EuroLeague player can belong to only one manager league-wide (draft mode).

Before each round, a manager picks an active squad of 10 from their 13 - the other 3 are excluded and score zero, no matter what. Within the active 10:

5 Starters
Full points. One is captain and doubles (2x) their score.
1 Sixth man
Full points too, but never captain-eligible.
4 Bench
Half points - automatic, whether or not they're ever swapped in.

The 5 starters must form one of three valid shapes: 2-2-1, 2-1-2, or 3-1-1 (Guard-Forward-Center) - always at least 2 Guards. A round is played over two days; points from day 1 are banked permanently, and on day 2 you can swap a full-scoring slot for a same-position bench player who still has a game left, promoting them to full points. Team win gives a +10% bonus to that player's round score. Full detail (including the day-1/day-2 "golden rule") is in docs/game_rules.md in the repo.

The Lineup page applies all of this for a chosen manager and round - see "Lineup builder" below.

Scoring: PIR

PIR (Performance Index Rating) is the fantasy currency, not raw points:

Point scored, rebound, assist, steal, block performed, foul drawn+1 each
Turnover, block suffered, foul committed, missed shot/free throw-1 each

How projections are calculated

Deliberately simple and auditable - no machine learning. For each player, using only games strictly before the projection date (so it never "cheats" by seeing the future):

Projected value ("Proj+Bonus")
A recency-weighted average of the player's last 10 played games (more recent games count more), plus a bonus scaled to their team's win rate over its last 10 games (+10% of the base projection if the team's been winning consistently).
Games sampled ("n")
How many of the last-10 games actually went into that average. Fewer than 3 games and no projection is built at all - too little signal.
Which season's data
If the current season already has synced games, only those count. Otherwise it falls back to using all of last season's games. This is a hard switch, not a blend - early in a new season, a returning player with only 1-2 games so far can temporarily show as unprojected until they hit 3 games in the new season.

The draft board

VORP
Value over replacement: how much better a player projects than the last player at their position who'd plausibly still get drafted across all 12 managers. Makes positions comparable - a scarce Center can rank above a slightly-higher-projected Guard once scarcity is factored in.
Tiers / "tier break"
Within a position, a tier break marks an unusually large drop-off to the next player (bigger than that position's average gap). Players within the same tier are roughly interchangeable - if your target gets drafted, don't reach for a specific name, grab anyone else in that tier. Only shown in the default sort (Projected value, high to low) - it's not meaningful once you re-sort by something else.
NEW badge
This player has no EuroLeague box-score history in this project's local data (E2023 onward) - a new signing, a rookie, or a club new to the league itself. Their projection is a placeholder of 0.0 rather than a guess, since there's genuinely no data yet to base one on. Their team still shown correctly, pulled from the current roster sync rather than box scores.
Filter and sort
Filter by position and/or team, and sort by any column (value, VORP, games sampled, name, or team), ascending or descending.

Draft, ownership, and transactions

Someone (the commissioner) manually logs what actually happens in the real league: draft picks, trades, free-agent adds, and drops. A player can only be owned by one manager at a time - drafting or trading for an already-owned player is rejected. A trade is logged as a linked pair (a shared "group" ID ties the two legs together in the transaction history). Transfer windows sit between rounds in this league, not continuously open.

Transfer suggestions

For a manager's full 13-player roster, this looks for same-position upgrades: any unowned free agent projecting meaningfully higher than a rostered player at the same position. It's naive by design - it doesn't account for a manager's active-squad exclusion choices or bye weeks, just raw projected value at the same position.

Lineup builder

For a chosen manager and round, picks which 3 of the 13 roster players to exclude, builds the day-1 starting lineup, and separately shows the swap plan to apply once day 1's games are finished - see "The league's rules, in brief" above for the three-tier scoring model and the day-1/day-2 golden rule this follows exactly. Exclusion is chosen by trying every possible 3-player exclusion (286 combinations - cheap) and keeping whichever leaves the best lineup, since a benched player keeps swap-in option value an excluded player doesn't. Needs the season schedule to be synced for the round in question - the regular box-score sync (see below) now also refreshes it. Like Transfer suggestions, this is a live, recomputed-on-every-visit recommendation, not a saved record of what a manager actually did.

Keeping the data fresh

This app only ever reads the local database - it never calls the live EuroLeague API itself, so pages load fast and never hit a rate limit. Someone with terminal access needs to run these periodically:

sync_db.py
Pulls newly played box scores (run after each gameweek).
sync_rosters.py
Refreshes current club rosters (run before a draft, or whenever transfer news breaks - not tied to gameweeks).

If the draft board looks stale (wrong teams, missing new signings, or projections not reflecting recent games), that's the fix.
